# ARCHITECTURE.md: Spawn Prawn system map

Reference map of every system: which files own it, what it reads and writes, and where it hooks in. Use the **system names** (left column, in bold) in the "Systems" line of `changes/<branch>.md` fragments. Keep this file in step with the code: a new file, a new system or a moved responsibility means an edit here in the same commit.

## Layout
- `web/`: the game. `index.html` loads `style.css`, `eink.css` (eInk view only) and `js/*.js` as plain scripts (no build step, no modules, globals in script order).
- `android/`: WebView wrapper, Gradle project. Release signing via `spawnprawn.keystore` + `SPAWN_KS_PASS`.
- `release/SpawnPrawn.apk`: the shipped build.
- `tests/`: Playwright tests (`run.sh`), sims (`tests/sim/`), tools (`tests/tools/`: `guide.js` builds `GAME_GUIDE.md`, `mouth.py` builds level maps, `copy/copy.sh` syncs `SpawnPrawn_Copy.xlsx`, `atlas/atlas.js` builds the Weapon Atlas page from `atlas/template.html`; `sim/framebench.js` times a late Race frame; `sim/modaudit.js` runs every weapon x Delivery x modifier the draft can offer in a fixed arena and reports the modifiers that change nothing (NO-OP) or only numbers (NUMBERS)).
- Docs: `CLAUDE.md` (rules), `NOTES.md` (current state), `changes/<branch>.md` (per-session change log) and `CHANGELOG.md` (folded on merge into `main`), `STYLE.md` (visual style), `GAME_GUIDE.md` (generated player guide), `WEAPON_IDEAS.md` / `FEAT_IDEAS.md` (idea banks), `log.md` (run log reviews), `ENEMY_STATS.md` / `ENEMY_BEHAVIOUR.md` (generated enemy tables, `tests/tools/enemytables.js`), `ENEMY_HANDOFF.md` (the enemy optimisation task list, 25 Oct 2026), `ENEMY_COPY_BRIEF.md` (stale enemy text for the user to rewrite), `MODAUDIT_HANDOFF.md` (modifier audit tasks).

## Core spine
Everything else hangs off these. `data.js` and `game.js` load first; `ui.js` loads last.

| System | Files | Role |
|---|---|---|
| **data** | `data.js` | Static tables: `ELEMENTS`, weapons, `SPELLS` (Feats), merges, passives, enemies, bosses, `REACTIONS`, `PAL`. |
| **settings** | `settings.js` | `SET` (`sd_settings`), `SETTINGS_DEF` with tabs, hints, `off()`, sliders; narrator packs. |
| **meta** | `meta.js` | `META` (`sd_meta`): DNA, Gene Bank, unlocks, `APP_VERSION`. |
| **engine** | `game.js` | `G` run state, `newGame`, `update(dt)`, combat (`damageEnemy`, `killEnemy`, `fireWeapon`), AI, director/spawning, XP, `computeStats`, loot (`genLoot`, `rollRarity`, novelty `novK`). Most hook calls start here. |
| **hooks** | `hooks.js` | The event hub: `hookOn(ev, name, fn, order)` registers a feature for a core moment; `game.js` fires them with `hookRun` / `hookMul` / `hookFirst` / `hookSafe`. Events: `hit:before`, `kill:before`, `kill:early`, `kill`, `kill:after`, `dmgMul`, `proc`, `hit:late`, `hurt:before` (change or cancel a hit), `hurtMul`, `hurt`, `hurt:late`, `fire:before`, `fire`, `fire:after`, `tick` (arguments in the file header). `killEnemy`, `damageEnemy`, `hurtPlayer` and `fireWeapon` are thin entries round a `...Body`; prefer a :before/:after listener to wrapping them. Also holds the wiring moved out of `game.js` in its old order. |
| **render** | `render.js`, `icons.js`, `grants.js` (colour switches: Lab vs Arcade) | World and HUD drawing: floor, lights, entities, egg, swimmers, minimap; `col()`/`RAW_COL`; weapon icons and type colours. |
| **ui** | `ui.js`, `loadout.js` | DOM screens: title, samples, loot cards (`UI.openLoot`, `UI.pickLoot`), pause, end screen, Tackle Box (Loadout tab in `loadout.js`). |
| **uikit** | `uikit.js` (after `settings.js`) | One HTML builder per design-system component (`uiPanel`, `uiHint`, `uiChip`/`uiChips`, `uiTabs`, `uiTile`/`uiTiles`, `uiList`, `uiButton`, `uiSectionHead`, `uiSampleCard`, `uiTraitRow`, `uiDamageRow`, `uiLoadoutTab`, `uiModSlot`, `uiPanelOpen`/`uiPanelClose`, `uiLootCard`, `uiLootSection`, the HUD parts and `uiBossCard`), matching the Figma Components page. Menus build their HTML from these; `#hud` (`uiHud`) and `#bossIntro` (`uiBossIntro`) are empty in index.html and filled by uikit.js as it loads. Colours and spacing come from the design tokens at the top of `style.css` (`--color-*`, `--space-*`, `--radius-*`), named like the Figma variables. |

## Cross-cutting rules
- **Hook-file pattern**: a feature lives in its own file. Where `hooks.js` has an event for the moment (a kill, a hit, a multiplier on damage dealt or taken, being hurt, firing, each frame), the feature registers with `hookOn(...)` from its own file and `game.js` is not edited. Otherwise `game.js`, `render.js`, `ui.js` and `bosses.js` get one-line calls into it. Each file's header comment lists its hooks. Add the file to `index.html` in the right order.
